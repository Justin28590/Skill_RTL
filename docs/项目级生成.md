# 项目级模型生成：协议、信任边界与验收

## 运行入口和状态

- 默认：`configs/glm.json` → `data/project-rtl/tasks.json`，32个完整多模块IP，包括脉动阵列、FMA、DMA、共享存储和异步流互连。
- 语言：Verilog、SystemVerilog、Chisel；目标分别可选27、30、2项。没有单文件fallback，不支持的任务/语言组合在调用模型前拒绝。
- 数据为`pilot`，未冻结dev/test。原生语言27/3/2独立统计，不按翻译目标重复计数。
- 主实验只保留Baseline/Skill两组，同模型、需求、工具链及修复/重构预算，仅切换Skill加载。默认每组最多2次功能修复、1次低分重构。Skill加载机制、Verilog/SystemVerilog评分公式及验证器不变；新增Chisel源码评分采用同样的五项权重，不是依据新任务成绩优化设计规则。
- `tasks.json`是唯一任务入口，同时描述参考验证和候选生成；`sources.lock.json`只锁定上游版本与文件。运行证据按需生成到本地输出目录（验收命令使用`artifacts/`），不随仓库保留，也不参与任务加载；修改验证器后重新执行，不回填旧证据哈希。

## 多文件响应

最终回答仅包含对象 `{"files":[{"path":"rtl/top.v","content":"..."}, ...]}`，也接受一个包住整个对象的JSON围栏。不接受额外说明、第二个对象、build脚本或增量diff。

- 对象/条目键集合固定；所有层级拒绝重复JSON键。
- 文件1～128个；源码总计≤2,000,000字节（含补齐的末尾换行）；响应文本≤4,000,000字节；路径≤160字符。
- 只接受ASCII相对路径；拒绝绝对路径、点/父目录/空段、隐藏段、反斜杠、大小写伪装后缀、重复路径及文件/目录前缀冲突。
- Verilog允许 `.v/.vh`，SystemVerilog增加 `.sv/.svh`；Chisel仅`.scala`。必须有源文件，不能只交头文件。
- 所有子模块与include文件随响应提供。不允许外部网表/黑盒、TB、外部库、VPI/DPI、宿主I/O或任意层次引用。
- include必须独占一行，形如 `` `include "rtl/defs.vh" ``，其值以项目根目录为基准，不能是宏或拼接表达式。允许本地常规宏和条件编译；禁止token拼接/字符串构造绕过检查。
- 文件按路径排序预处理/编译；SystemVerilog接口、复杂package依赖和结构体点成员可能不被保守策略接受。项目规模支持不等于完整语言支持。

每次生成/修复/重构先完整解析，随后写入新的attempt目录。上一轮文件不会补齐本轮缺失项。最终交付也重建完整树，防止遗留失效子模块；失败重构按完整bundle回退。

## 公开信息与隐藏评测

模型可见：

1. `specs/<id>.md`：公开顶层声明、参数、寄存器/行为约定、时序/算法边界、编译宏/方言和上游公开说明。
2. 外层产物协议和源码限制。
3. 仅Skill组通过只读 `read_skill` 白名单读取的指导文档；Baseline不加载。
4. 修复时的上一轮完整候选、候选编译错误和粗粒度失败原因。

模型不可见：参考RTL正文、隐藏TB、仿真向量/期望值/原始仿真日志、DUT内部断言名字、源文件锁定清单。所有工具调用仍限于Skill白名单；公开文件中的文档链接并不授予任意文件读取。

本地报告可以包含完整评测日志，属于审计材料；**不会作为repair消息发送**。涉及候选＋TB的编译错误统一反馈 `trusted_testbench_link_failed`；仅候选预处理/编译失败允许返回脱敏的候选诊断。功能失败只返回类别，不给期望答案。

## 原版TB的独立适配层

`data/project-rtl/sources/`中的RTL/TB和原版参考证据保持不变。`tests/adapted/`是单独、可再生的候选评测层，不能冒称逐字节原版TB：

- 移除只用于dump的 `dut.<内部寄存器>` / `dut.core.*` 调试输出；保留实际外部功能检查。
- CMAC原TB在reset和密钥派生测试中检查内部寄存器。改为公开ID/寄存器复位读回、ready状态以及已有MAC结果检查，不要求候选复制K1/K2或内部实例命名。记录减少内部结构断言的覆盖边界。
- 将可信TB的普通不等比较强化为四态不等，防止X/Z绕过原来的 `if (actual != expected)`。
- USB测试显式导入其不可变协议常量，不依赖候选宏泄漏。
- CPU额外增加数据集自编的独立AXI检查实例：在测试侧生成RV32算术/M扩展与load/store程序，核对64次真实存储结果。期望值不进入CPU地址空间，不以软件控制的console字符串或PASS寄存器为唯一答案；仍要求原45份ISA套件全部通过。该新增TB不是上游原版，也不是穷尽ISA/IRQ验证。
- 完整DUT的公开接口和内部实例层次由Icarus实际展开结果检查，不靠计数源码中的 `module` 字样。

差异及原文件SHA在 `tasks.json` 各项目的 `generation.testbench_adaptations` 中记录；候选TB、公开契约、测试依赖均锁定哈希。原版参考验证与候选适配层验证是两份独立证据。

## 候选验证顺序

1. **快照与路径检查**：磁盘文件必须与已解析响应一致，无符号链接或路径逃逸。
2. **仅候选预处理**：工作目录只含候选，include路径仅该目录。项目编译宏来自公开契约。
3. **展开后策略**：只允许 `$clog2/$signed/$unsigned/$bits`；拒绝文件/进程/仿真I/O、force/release、bind/defparam、DPI、层次引用等。不能靠宏藏起危险构造。
4. **仅候选编译**：所有公开顶层作为根，缺失依赖直接失败；禁止由可信TB偷偷提供设计模块。检查必需公开parameter确实可覆写，不能改成localparam或删掉。
5. **与可信TB链接**：使用预处理后的候选，不再次导入候选宏；重置其全局编译指令环境。必要时为原版Verilog TB使用1364-2005关键词域，避免`int`等旧标识符被SystemVerilog误解。测试头文件与候选include目录隔离。
6. **接口/层次**：每个公开DUT根的模块、端口名、方向和实例化宽度必须一致，缺失参数覆写警告也算失败。每个DUT根至少含一种实际子模块，所有公开顶层必须被测试执行；子模块命名/数量允许不同于参考。参数覆写后真正展开的每个DUT模块类型也必须在候选中定义，不能借用TB辅助模块补齐默认配置未展开的分支。
7. **仿真判据**：全日志无失败标记，全部正向标记达到要求次数，且正常退出；失败标记优先。超时/缺少标记不是通过。

项目级可选Lint明确为 `not_run`；可读性启发式作用于按路径排序拼接的候选源文件，Verilog/SystemVerilog方法名和权重不变；新增Chisel专用源码评分，详见[源码可读性评分](源码可读性评分.md)。不能用文件数或高分替代实际功能验证，也不能保证子模块都有实质逻辑；多层次检查＋有限测试仍不等于防投机的穷尽证明。

## Chisel项目后端

`src/rtlflow/chisel.py`在上述HDL验证前增加Scala策略检查及编译/展开：

- 可信宿主创建build.sbt、project/build.properties和RTLFlowMain，不接收候选构建脚本、插件、main/App或外部RTL。
- 固定JDK17、sbt1.10.7、Scala2.13.12、Chisel6.5.0、firtool1.62.0；调用`runMain RTLFlowMain`，禁止随机初始化，保留子模块。记录工具可执行文件、构建文件、生成RTL的哈希。
- `chisel_tops`声明类、包、固定整数/UInt构造参数，可描述多个顶层；当前数据只有两项单顶层多模块IP，不宣称多顶层数据覆盖。不同顶层生成同名且内容不同的文件时失败，不静默覆盖。
- 只从当前候选源码树编译，不链接参考RTL、不复制隐藏TB到Scala构建目录。子进程使用精简环境，不继承GLM_API_KEY。这不是安全沙箱；任意Scala仍具有宿主执行风险。
- 生成RTL再经过相同的路径、源码策略、预处理、候选编译、接口、实际层次和独立TB检查；禁止手改生成RTL来绕过失败。
- 缺工具记`not_run`；编译/展开失败记`failed`，可限轮修复。默认展开超时300秒，可通过`chisel_timeout_seconds`配置（上限600）；首次构建可能访问Maven下载固定依赖。
- `final/`交付Scala；`final-rtl/`交付被选择轮次的展开RTL。源码和RTL哈希分开。Chisel采用`static-chisel-heuristic-v1`直接评分Scala源码；Baseline/Skill均可按同预算尝试低分重构，重新展开并通过功能验证且分数严格提高才接受。
- 不支持Verilog运行时参数覆写、Analog/inout适配、BlackBox/外部资源。不能对Verilog任务任意指定Chisel并声称功能等价支持。

## 修复与回退

格式、路径、缺模块、编译、接口、层次或功能失败均可进入repair轮次，两组共用相同反馈裁剪和预算。API错误、截断及Skill加载失败不会自动改用参考实现或mock。

两组均只在已通过功能且分数低于相同阈值后尝试重构；只有**新项目全部验证通过且原评分严格提高**才替换旧项目。格式错误、功能退化、分数下降/持平、工具缺失或API错误均保留此前通过的整个项目。

报告schema 4记录完整bundle哈希、逐文件哈希、每轮source/checks、选择理由、首次/最终状态、真实HTTP尝试及Skill加载证据。源码评分的`readability_score`、`readability_status`和`readability_method`也记录于最终报告、CSV及逐任务对照；逐项扣分见`attempts[].readability`。`effective_max_repairs`与`effective_max_refactors`也进入CSV和逐项目对照，区分相同预算上限与实际使用次数；Skill读取的额外HTTP/token/耗时不视为总成本相同。`final_source`/`final_rtl`为目录，`final_bundle`为JSON文件；旧报告消费者需要适配。

## 离线验收与复现

三语言全量命令、证据路径及回归覆盖统一见[验收说明](验收.md)。原版参考验证不使用适配TB；候选回放执行与模型相同的验证链。

回放脚本是显式验证工具，不在providers或正常生成流程中调用。复制锁定参考源码时按文本读取（换行归一化）；USB复制件另外去掉恰好两条 `$display` 诊断以满足候选策略，不改变原版文件。原版测试自身的非综合构造不受候选策略约束。

回归还覆盖：即使输出全部旧CPU软件成功字符串，独立AXI算术结果错误仍必须拒绝。

负向对照在**可信测试侧**额外加入force模块，模型不得生成force。只有编译成功、候选功能失败且出现明确失败标记或仿真错误退出，才算负向有效；单纯超时或缺少成功标记不算证据。每份报告记录fault模块哈希。

`--compact`清理可重建的vvp、VCD、固件副本和sbt target缓存，保留源码、命令、日志和报告。记录保存在 `artifacts/project-rtl/candidate/`，没有付费模型调用；这些通过率不能作为模型生成成功率。

候选适配层/接口元数据的再生入口：`python3 scripts/prepare_project_generation.py`。它更新 `tests/adapted/` 和 `tasks.json` 中的 `generation` 字段，不重写 `specs/`；需求以单份受审阅文件为准，不再从另一份入库说明拼接。它需要Icarus及上述Chisel工具链，不运行上游构建脚本；首次Chisel构建可能下载固定Maven依赖。前一轮六项目的固定归档导入入口为`scripts/expand_project_dataset.py --download`；脉动阵列/交换器导入为`scripts/expand_compute_dataset.py --download`，本轮四项导入为`scripts/expand_modern_dataset.py --download`，均显式联网并校验归档哈希，保留同仓库已锁定的文件。详见[计算与互连案例](计算与互连案例.md)。修改契约、适配层或验证器后必须重跑相应证据，不能只改旧报告里的哈希。

## 尚未完成及安全边界

- Chisel任意参数配置/双向端口适配尚未接入；源码可读性仅为词法启发式，两项固定配置通过不能外推所有Chisel工程。
- 未冻结dev/test；AES/CMAC依赖共享、算法族及新增同仓库项目必须在后续拆分时处理。当前15/32项目为密码类，不代表均衡工业分布。
- 有限TB不覆盖所有配置/模式，也不证明标准完全符合、可综合性、PPA、等价性或密码安全。
- 编译和仿真有墙钟超时/进程组终止，但无完整内存/磁盘配额，不是沙箱。需在可信本机使用，外部不可信项目另加无网络、非特权资源隔离。
- 没有正式真实模型成绩，也没有自动Skill跨任务优化。

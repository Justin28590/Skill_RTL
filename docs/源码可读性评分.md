# 源码可读性评分

入口：`src/rtlflow/score.py::score_readability(code, language)`。仅使用Python标准库，不执行源码，不需要JDK、sbt或模型服务。Chisel实现位于`src/rtlflow/chisel_score.py`。

| 语言 | 报告中的 `method` | 评分对象 |
| --- | --- | --- |
| Verilog | `static-heuristic-v1` | 候选Verilog源码，原规则不变 |
| SystemVerilog | `static-sv-heuristic-v1` | 候选SystemVerilog源码，原规则不变 |
| Chisel | `static-chisel-heuristic-v1` | 候选Scala源码，**不是展开后的RTL** |

三者均为可复现的静态启发式，不是语义质量评价，**不能用于跨语言排名**。同语言比较也应锁定方法版本和工程规模；按问题数量扣分会受代码规模影响。

## Chisel v1量表

每项分数为 `max(0, 权重 - 单次扣分 × 问题数)`，总分为五项之和，范围0～100。

| 维度 | 权重 | 检查与扣分 |
| --- | ---: | --- |
| `naming` | 25 | `val/var/def/class/object/trait` 后的单字符声明名；也识别简单元组及 `val idle :: busy :: Nil` 绑定。名称去重后每个扣3分，豁免 `i/j/k/_`，不把泛型参数 `T` 当变量。不会要求修改契约规定的接口名。 |
| `structure` | 25 | 同行分号后仍有语句，每个问题行扣3分；单个行尾分号不扣分，`for (...)` / `for {...}` 枚举器分隔符豁免，循环体内多语句仍检查。 |
| `complexity` | 20 | 全源码最大花括号深度超过3扣5分（包含类、Bundle、作用域，不等于硬件逻辑深度）；嵌套 `Mux(...)` 每个问题行扣5分，可跨行识别，不惩罚并列调用。 |
| `comments` | 15 | 没有非空注释扣10分；支持行注释、块注释和Scaladoc，只检查存在性，不评价设计意图的真实性或质量。 |
| `style` | 15 | 制表符、尾随空格、超过100字符，每种问题每行扣1分；原始源码的注释/字符串行也计入格式检查。 |

命名、结构和复杂度检查前会屏蔽注释、普通/三引号字符串和字符字面量，保留行号；支持Scala嵌套块注释。字符串中的 `//` / `/*` 不算注释，字符串/注释中的声明、分号、花括号和Mux不造成结构扣分。简单插值字符串整体屏蔽，**不分析其中的表达式**；含嵌套引号的复杂插值不完整解析，可能误判。

这是轻量词法分析，不完整解析Scala AST、构造/方法参数、复杂模式绑定、类型、隐式转换、别名或所有Mux变体。分数不证明能够编译、成功展开或满足硬件语义；高分不代替独立仿真、Lint、人工盲评、综合或形式验证。

空白或纯注释输入返回 `status=not_run`、`score=null`、`reason=no_scala_code`。其他输入的 `status=passed` 只表示评分已执行，**不是功能通过**。不能据分数跳过源码策略或编译验证。

## 多文件与闭环

- 正常流水线只评分成功解析的完整候选bundle。源文件按路径排序后以换行连接，记录 `project_file_order`；问题行号相对于该拼接文本，不是单文件行号。JSON、宿主生成入口和展开RTL不参与评分。
- 即使工具缺失或功能失败，只要有可评分源码仍可报告分数；功能状态单独记录。这样既可分析全部样本，也可单独分析功能通过样本。
- `attempts[].readability` 保存 `method`、`language`、`status`、`score`、逐项 `dimensions` / `issues` 和 `limitations`。最终报告、CSV和逐任务组间对照均记录 `readability_score`、`readability_status`、`readability_method`。
- Baseline/Skill共用评分规则、阈值和重构预算。默认阈值95、最多1次重构；只有功能已通过且低于阈值才尝试。无分数、功能失败/未运行或预算为0时不重构。
- Chisel重构必须返回完整Scala项目，重新执行编译、展开、HDL接口/层次与独立仿真；**功能通过且源码分数严格提高**才接受，否则回退整个源码及对应展开RTL。不能通过修改生成RTL提高源码分数或绕过验证。

本次新增Chisel方法；既有Verilog/SystemVerilog公式、权重、验证策略和预算不变。此前Chisel `not_run` 的历史报告保持原样，不补写或伪造旧实验分数。正式实验前应冻结评分器和Skill版本。

## 验证

```bash
# 量表、词法边界、原HDL评分兼容、两组评分反馈/接受/回退、报告字段
python3 -m unittest discover -s tests -v

# 显式启用真实Scala/Chisel展开及独立HDL仿真，无付费模型调用
RTL_CHISEL_INTEGRATION=1 python3 -m unittest discover -s tests -p 'test_chisel.py' -v
```

`tests/test_chisel_score.py` 使用真实评分器和模拟验证状态覆盖两组闭环；`tests/test_chisel.py` 的显式集成测试使用真实sbt和Icarus，验证注释改善被接受、源码评分提高但FIFO输出损坏被拒绝，以及源码/RTL成对回退。这些是离线实现验收，不是模型生成成绩或人工可读性评价。

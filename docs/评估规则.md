# 评估规则

本规则用于判断 Skill 修改是否改善生成结果；优化步骤见 [README](../README.md)，执行命令见[运行与验证](运行与验证.md)。

## 实验口径

- 比较 Baseline、旧版 Skill 和新版 Skill；固定模型、采样参数、任务、工具链、评分、反馈和修复/重构预算。组间不共享候选或对话；相同预算上限不代表实际成本相同。
- 当前数据仍为 pilot，未冻结 dev/test。正式实验须按来源、共享依赖和算法族隔离开发/测试集；如 AES/CMAC、DMA/共享 RAM、AXI-Stream FIFO/交换器/异步桥不能随意拆开。冻结后不得根据测试结果调规则再声称独立评估。
- 同时报首次/最终功能通过率、可读性、修复成功率、调用量/token/耗时及重复运行波动；保留失败和缺失结果。可读性分别报告全部样本、功能通过样本和双方均通过的同题配对结果。
- 正式人工盲评至少20组同题代码，隐藏组别/版本，由三人独立评价并统计一致性。启发式分数、工程回归和参考回放均不能替代真实模型实验与人工评价。

## 设计与验证前置门

主流程统一接收高层需求，不再接收旧固定接口清单。全部案例按[设计流程](设计流程.md)生成设计、独立审查、冻结契约，然后独立生成/审查并冻结TB，最后实现RTL。所有准备阶段均单独计费和报告；失败记`not_run`，不能算RTL功能失败。

验证模型与实现模型上下文隔离，但默认使用同一provider/model；Skill组的各阶段还加载同一份公共Skill，可能产生共享偏差，不是人工或可信数学oracle。TB必须通过编译、恒零/恒一负控和独立审查。冻结后不能根据候选改测试或契约。两组需求、阶段协议和预算一致，但自主设计和TB可能不同，须报告冻结哈希及额外波动，不声称严格同接口同测试配对。

## 可复用Skill与评测适配边界

`skills/rtl-readable/`是可独立复制的用户Skill：在授权范围内读写实际工程、设计接口、编写TB、调用已有工具并交付文件；不依赖本仓库或评分器。其默认修复上限、目录建议和交付方式用于普通工程，不是本评测的运行协议。

评测专属约束由设计/验证/实现阶段提示、`skill_tools.skill_capabilities`和验证器施加，不写回通用Skill：

- Skill覆盖完整模型流程：设计/契约修订、独立设计审查、独立TB准备/修订/审查、RTL实现/修复/重构。每次只执行本阶段职责，不自行启动其他阶段或额外修复循环；Baseline各阶段不加载Skill。
- Skill组每次调用先用`read_skill`读入口，再读通用/所需语言规则及对应参考；仅这三份文档可读。设计/设计审查/RTL使用DUT目标语言，TB准备/审查使用SystemVerilog。每轮重新加载，不共享工具会话；不能读取工程、隐藏测试或参考源码，不能执行命令、联网或写文件。
- 各阶段按各自协议交付：设计JSON、审查JSON、验证JSON或RTL完整`files` JSON，由宿主落盘；不把RTL阶段的“禁止生成TB”约束用于验证准备。文件数/大小、路径、include、源码策略、实际子模块层次及Chisel固定工具链等约束以下述协议和系统提示为准。
- 验证、评分、修复轮次和整项目回退由控制器负责。模型不得把Skill中的工程操作建议当作额外权限，也不能声称自行运行了工具。
- 普通用户可授权使用工程支持的package/interface、断言、BlackBox等；本评测的保守子集仍可能拒绝它们。评测策略限制不代表这些结构在语言中普遍非法。

因此，相同Skill可用于用户工程和受控评测；评测适配只限制能力和输出，不复制另一份Skill或把框架细节混入编码规则。

## 完整项目交付

每轮只返回一个完整 JSON 对象，允许单个 JSON 围栏；不接受解释、补丁或沿用上一轮文件：

```json
{"files":[{"path":"rtl/top.v","content":"<完整源码>"},{"path":"rtl/core.v","content":"<完整源码>"}]}
```

- 仅允许上述键，拒绝重复 JSON 键。1～128个文件，源码合计≤2,000,000字节，响应≤4,000,000字节；路径≤160字符。
- 路径必须为 ASCII 项目内相对路径；拒绝绝对路径、点/父目录/空段、隐藏段、反斜杠、重复路径和文件/目录冲突。
- Verilog 用 `.v/.vh`；SystemVerilog 另允许 `.sv/.svh`；Chisel 仅 `.scala`。必须包含实际源文件及全部子模块，不交 TB、构建脚本、外部库或黑盒。
- HDL include 必须独占一行，使用相对项目根目录的双引号字面量，文件随响应提供。允许常规本地宏，禁止宏拼接、外部 include、层次引用、宿主 I/O、仿真系统任务、VPI/DPI、`force/release/bind/defparam`；系统函数仅允许 `$clog2/$signed/$unsigned/$bits`。
- 策略只支持保守语言子集；复杂 package/interface 或结构体访问不保证支持。Chisel 不接收 main/App、自带 emitter 或外部 RTL，使用设计阶段冻结的构造配置，不支持生成RTL的参数覆写。

## 信息与功能判定

RTL实现/修复模型只接收公开契约、交付规则、上一轮候选和裁剪反馈；前置阶段的输入边界见[设计流程](设计流程.md)。Skill 组每个模型阶段都必须通过 `read_skill` 读取入口、通用/目标语言规则及对应语言参考；工具不能任意读文件或执行命令。参考源码、隐藏 TB、向量/期望值、原始仿真日志和凭据不得进入生成或修复上下文。

验证顺序：

1. 核对完整快照、路径、哈希和磁盘文件一致性，拒绝符号链接。
2. Chisel 先由可信宿主生成构建文件并编译/展开，不读取参考 RTL；生成 RTL 再走以下同一验证链。
3. 仅候选预处理及展开后策略检查，再以全部公开顶层独立编译；缺失模块不能由 TB 或参考实现补齐。
4. 与独立生成并冻结的TB链接，隔离候选宏、编译指令和include；连接及参数实例化由宿主按冻结契约构造，而非复用旧端口/时序。核对顶层端口、方向、实例化位宽及可覆写参数。
5. 检查实际展开层次：每个公开顶层须受测且有实际子模块；参数分支也不能借用 TB 的设计模块。内部命名和子模块数量不要求复制参考。
6. 独立仿真须正常退出、所有正向标记达到规定次数且完整日志无失败；失败标记优先。**编译成功、退出码0或单个 PASS 字符串均不足以判通过。**

只返回脱敏的候选编译/展开诊断；涉及TB的链接错误和功能失败仅给粗粒度原因。本地完整日志只供审计。每轮检查冻结契约、需求和测试哈希，禁止根据候选删改检查。CPU等复杂案例应在独立TB审查中检查结果scoreboard，不能只信软件打印；模型审查不保证覆盖完备。

`passed` 表示实际通过，`failed` 表示实际失败，`not_run` 表示工具缺失或前置条件未满足。项目级 Lint 未接入，始终单独报 `not_run`。有限仿真及层次检查不证明所有配置正确、形式等价、可综合性、PPA或物理 CDC。

## 可读性评分

入口为 [`score_readability`](../src/rtlflow/score.py)，Chisel 实现在 [`chisel_score.py`](../src/rtlflow/chisel_score.py)。按路径排序拼接候选源码，不评分 JSON、宿主构建入口或 Chisel 展开 RTL。

| 语言 | 方法名 | 评分对象 |
| --- | --- | --- |
| Verilog | `static-heuristic-v1` | Verilog 源码 |
| SystemVerilog | `static-sv-heuristic-v1` | SystemVerilog 源码 |
| Chisel | `static-chisel-heuristic-v1` | Scala 源码 |

每项为 `max(0, 权重 - 单次扣分 × 问题数)`，总分0～100：

| 维度 | 权重 / 单次扣分 | 检查 |
| --- | --- | --- |
| 命名 | 25 / 3 | 可识别声明中的单字符名，去重，豁免循环名 `i/j/k`；Chisel 另豁免 `_` |
| 结构 | 25 / 3 | HDL 同行多个分号（for 行豁免）；Chisel 分号分隔的多语句（for 枚举器豁免） |
| 复杂度 | 20 / 5 | HDL begin/end、Chisel 花括号最大深度超过3；另查 HDL 同行多个 `?` 或 Chisel 嵌套 Mux 问题行 |
| 注释 | 15 / 10 | 缺少非空注释；仅检查存在，不判断质量或真实性 |
| 风格 | 15 / 1 | 每行每种制表符、尾随空格、超过100字符问题各扣一次 |

这些是词法启发式，不完整解析语言、硬件结构或注释含义；不能跨语言排名，同语言也受代码规模影响。Chisel 屏蔽嵌套注释和字符串，简单插值整体屏蔽，复杂插值可能误判；空白/纯注释 Scala 返回 `not_run`、`score=null`。评分状态不等于功能状态，功能失败的可解析源码仍可评分；不得为命名分数改公开接口。

逐项证据在 `attempts[].readability` 的 `dimensions` / `issues`；问题行号相对拼接文本，文件顺序见 `project_file_order`。最终分数、状态和方法分别记录为 `readability_score`、`readability_status`、`readability_method`。正式实验需冻结评分器。

## 修复与选择

两组默认最多1次设计修订、1次验证环境修订（每版各有独立审查）、2次RTL功能修复和1次可读性重构，以配置为准；API、截断或Skill加载失败不降级为mock，不回填参考源码。仅在功能通过且分数低于95时尝试重构，无分数时跳过；**新项目功能通过且分数严格提高才接受，否则保留此前通过的完整快照**。Chisel 源码与对应展开 RTL 必须成对回退，每次修改重新验证。

schema 6报告保存所有阶段逐轮状态、源码/文档哈希、调用成本及选择理由。`skill_by_phase`与加载计数区分前置阶段/RTL及完整/部分/未读取；`skill_loaded=true`仅表示至少一次完整加载，不等于完整流程通过。`final/` 存在不代表通过，应检查 `functional_status`、`selected_attempt` 和 `stop_reason`；`skill_version=tool-v1` 是加载协议，内容版本以读取哈希为准。运行期间不要修改 Skill，也不要回填旧实验记录。

**源码过滤、精简子进程环境和超时不是安全沙箱。** 不可信 HDL/Scala 必须在无网络、无密钥、非特权且有限资源的隔离环境执行。

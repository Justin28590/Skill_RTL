# 从需求完成硬件设计

唯一模型运行入口：**高层需求 → 设计说明与接口/时序契约 → 独立审查并冻结 → 独立验证环境准备/审查/冻结 → RTL → 独立仿真与限轮修复**。

适用于 [`data/requirements.json`](../data/requirements.json) 中全部32个案例及各自支持的目标语言。没有按任务 ID 选择旧 TB 的分支。`run.py` 不再接受旧 `project-rtl-v2` 固定契约清单；`data/project-rtl/` 仅保存来源、许可证和历史工具回归材料，不进入模型主流程。

## Skill 覆盖与隔离

Skill 组从第一次设计调用开始，**每次设计/契约修订、设计审查、TB准备/修订、TB审查、RTL生成/修复/重构均加载 Skill**；Baseline 全程不加载。宿主的结构校验、编译、仿真、评分和冻结仍由确定性脚本执行，不交给模型自行宣称通过。

| 阶段 | Skill 指导与允许交付 |
| --- | --- |
| 设计/契约修订 | 需求分析、接口/时序/参数自检；只交付设计 JSON |
| 独立设计审查 | 审查契约完整性与一致性；只交付审查 JSON，有问题拒绝 |
| 独立验证准备/修订 | 从需求与冻结契约生成自检查 TB 和独立 oracle；只交付验证 JSON |
| 独立验证审查 | 检查 oracle、覆盖、采样与时序；只交付审查 JSON |
| RTL生成/修复/重构 | 遵守冻结契约、功能优先、保行为重构；只交付完整 files JSON |

每次调用使用新的只读工具会话，先读取 `SKILL.md`，再读取 `rules.md` 的通用/所需语言分支和对应参考。未读全时请求 `tool_choice=required`，工具只暴露当前尚未读取的文档；读全后请求 `tool_choice=none`，转入阶段结果生成，避免重复读取耗尽预算。服务若忽略选择约束，提前返回正文或继续调用工具仍被拒绝，不伪造读取证据。设计/设计审查/RTL使用 DUT 目标语言；TB准备和TB审查统一使用 SystemVerilog 分支（包括 Verilog/Chisel DUT）。未读全三份文档的真实模型结果不被接受，不自动降级、不增加修复预算。阶段提示只规定角色、权限与交付协议，不把另一份设计规则写进脚本。

各阶段只获得规定的输入；同阶段修订可见上一版及反馈，Skill组的最新修订/修复/重构消息也明确要求在新会话重读三份文档，不能把上一版响应视为本轮加载证据。审查不继承生成对话，TB准备不见设计对话或候选RTL，RTL不见隐藏TB。共享公共Skill文档不等于共享会话。独立审查/冻结仍不可跳过，Skill 不能扩大文件/命令工具权限。

## 输入和产物

高层输入只有 `id`、`requirements_text`、`target_languages`。保留算法、标准、数值格式、业务能力及必要的外部约束；不要求沿用原端口名、参数名、寄存器地址或实现延迟。USB线级时序、AXI握手、ISA等外部标准不是可随意删除的实现细节。

设计提示与示例按目标语言生成：Verilog/SystemVerilog 不混入 Chisel 工具链/构造协议；Chisel 示例使用固定构造配置而非 RTL 参数覆写。要求模型返回一个完整 JSON 对象，不带 Markdown 或解释。解析层仅兼容包住整个响应的单个 `json` 代码围栏；不截取正文中的 JSON，不补全截断内容，不改字段。设计/审查/验证准备的原始 `response.txt` 保留，阶段报告中的 `json_wrapper_removed` 记录是否去除了外围代码围栏。重复键、多对象、前后解释、NaN/Infinity 仍被拒绝。

设计对象字段严格校验：

- `schema_version: 1`、`description`：架构、模块职责、算法与权衡。
- `tops[]`：仅列对外公开的独立入口，字段为 `name`、`parameters`（整数默认值）、`ports`、`timing`；内部子模块职责写入 `description`，不为内部叶子模块另建顶层/验证配置。
- 每个端口有 `direction`、`width`、`signed`、`description`。支持 input/output/inout；宽度为正整数或只含参数、括号及 `+ - * //` 的有界表达式，绝不执行 `eval`。
- `timing` 明确每个时钟域、采样沿、复位、输入接受条件、输出有效/保持、固定或可变延迟、吞吐、背压、边界与非法输入；组合模块也必须明确说明。时序语义目前由独立模型审查并转成 TB 检查，**不是完整形式化时序语言或机械证明**。
- `configurations[]`：`top` 与 `parameters` 覆写。每个顶层必须有不覆写参数的默认配置，并选代表性参数组合。
- `chisel_tops[]`：生成模块、全限定类名和安全构造参数。非 Chisel 为空；Chisel 使用固定展开配置，生成 RTL 不接受参数覆写。

结构校验拒绝重复键、非法名称、未知字段、无效位宽、遗漏默认配置等。非 Chisel 的 `chisel_tops` 非空、配置覆写未声明参数等一致性问题在可检查时合并反馈，指出配置位置、未知参数与已声明参数；不自动删字段或调整需求，修订预算不增加。随后独立审查调用只看到需求与提案，不看到设计对话；必须返回 `accepted=true`、空 `issues` 和非空审查依据，才写入 `design/frozen_contract.json`。设计文件同时绑定需求哈希、语言、契约与审查决定。

## 独立验证与可信边界

除公共 Skill 文档外，验证生成调用只有需求和冻结契约及宿主连接模板，**没有候选 RTL、参考源码、旧 TB 或设计过程对话**。它生成自检查 SystemVerilog 的模块内部 `body`、覆盖说明和独立期望值计算依据。

宿主按契约生成端口声明、参数配置和全部 DUT 实例；验证代码通过 `c0_<port>`、`c1_<port>` 等信号交互，不能自行替换 DUT。支持多顶层、多配置、组合逻辑、流水线、握手、多时钟及双向端口；具体协议和算术检查由独立生成的 TB 实现，不要求每个案例预写固定端口适配器。

冻结前的质量门：

1. 检查 TB 格式与受限源码策略；拒绝模块定义、外部 include、层次窥探、force/release、宿主 I/O 等。
2. 与宿主生成的恒零/恒一输出实现分别编译。两个负控都必须因带 `RTL_CHECK_FAIL` 的断言退出；编译失败、宿主超时或打印 PASS 不算有效负控。
3. 再用独立上下文审查需求覆盖、oracle、采样竞争、时序、恒失败/恒通过等问题。通过后冻结 `verification/frozen_verification.json`，绑定契约哈希。

这是**同一 provider/model 的独立上下文验证**，Skill 组验证者还使用同一份公共 Skill；不是不同模型投票、人工审核或可信数学 oracle。模型/Skill 可能带来共同误解，Skill 也会影响生成的 TB 强弱，因此组间通过率不是同一套可信测试下的严格配对；两个常量负控只能排除部分弱测试，不能证明测试完备。`passed` 仅表示通过本次冻结测试，不能沿用旧数据集覆盖率或声称32个复杂IP均已实测成功。正式成绩应加人工审查/可信算法 oracle/更强 mutation 或形式验证。

## RTL 与修复

RTL 模型只收到高层需求、冻结设计契约及实现规则。交付仍为完整 JSON `files` 快照；不包含 TB。Skill 已在此前各模型阶段加载，此处继续独立加载；两组采用相同阶段协议、修订上限和确定性质量门，Skill 的额外工具请求独立计费。

每轮重新校验需求、契约、TB的哈希及磁盘冻结副本，然后运行候选独立编译、端口/参数/实际层次检查及冻结 TB 仿真。只有全部必需检查通过才记为 `passed`。修复只得到候选诊断及粗粒度功能失败，不得到测试正文、期望值或原始仿真日志。

**不得在看到候选后重新生成或放宽 TB，也不得修复中改契约。** 契约/验证准备失败、工具缺失、冻结文件变化记 `functional_status=not_run`；修复预算不用于解决验证基础设施问题。需改变契约时以新运行目录重新开始。可读性重构仍要求功能通过且分数严格提升，否则回退完整源码及对应展开 RTL。

## 预算与报告

- `max_design_repairs=1`：最多2次设计，每次至多1次独立审查。
- `max_verification_repairs=1`：最多2次验证生成，每次至多1次独立审查。
- `max_repairs=2`、`max_refactors=1`：最多4次 RTL 候选生成。
- 因此每任务/语言/组最多12次 provider 调用；默认 Baseline 最多12次 HTTP，Skill 最多72次（全部12次阶段调用各最多6个工具轮次），两组合计84次。实际失败可提前终止；所有阶段的用量、耗时和错误都入账。

报告 schema 6（pipeline 0.6.0）包含 `design`、`verification_preparation`、两个冻结哈希、分阶段调用计数与 `attempts`（仅 RTL 轮次）。`stop_reason=design_not_frozen/verification_not_frozen` 区分前置阻塞。

Skill 证据覆盖全部阶段：

- `skill_scope=full_workflow` 表示 Skill 组的接入范围，Baseline 为 `none`。
- `skill_loaded` 表示至少一次调用完整加载；`skill_required_calls` / `skill_loaded_calls` 记录本次已尝试调用中需要加载/完整加载的次数。
- `skill_all_calls_loaded` 仅表示**已尝试的调用**全部完整加载，不表示所有阶段已执行或功能通过。`skill_by_phase` 列出各阶段次数及 `loaded/partial/not_loaded/not_run/not_requested`。
- `implementation_skill_loaded` 单独记录被选中 RTL 轮次的加载情况；设计已加载但尚未生成 RTL 时它仍为 false。
- `skill_documents` 是选中 RTL 轮次的证据；没有完整加载的选中 RTL 时，使用最近一次完整加载（或部分读取）的证据，`skill_evidence_phase` / `skill_evidence_prompt_path` 指明来源。不同阶段文档哈希不合并；每次读取的完整证据仍在该轮 `generation_metadata` 和 `agent_trace.json`。
- `summary.json` / CSV 汇总加载计数；模拟 provider 不伪造文档加载证据。

schema 5 的 `skill_loaded` 只描述 RTL 阶段。旧的 RTL-only Skill 实验与当前全流程 Skill 实验须分开统计，不能直接混算效果或成本。

```text
<task>/
  design/proposal_*/、review_*/、design.md、frozen_contract.json
  verification/attempt_*/、review_*/、frozen_verification.json
  attempt_00_initial/、attempt_01_repair/…
  final/、final.project.json、[final-rtl/]、report.json
```

所有阶段均为进程级过滤与超时，**不是安全沙箱**。生成 TB 同样是不可信代码；HDL/Scala执行仍应放在无凭据、无网络、非特权、有限资源的独立环境。

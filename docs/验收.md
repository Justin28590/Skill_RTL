# 离线验收与复现

所有验收均不调用付费模型；模拟 HTTP 和显式参考回放不是模型生成成绩。数据入口、项目数和许可见[数据集说明](../data/project-rtl/README.md)。

## 检查与回归

```bash
source scripts/env.sh
python3 scripts/project_dataset.py --check-data
python3 run.py --check-data
python3 run.py --language systemverilog --check-data
python3 run.py --language chisel --check-data
python3 -m unittest discover -s tests -v

# 显式启用真实 Scala/Chisel 编译与仿真
RTL_CHISEL_INTEGRATION=1 python3 -m unittest discover -s tests -v
```

普通回归默认跳过真实 sbt 集成，以及两项依赖本地历史验收产物的哈希检查；这些跳过不表示验证通过。工具缺失必须报告 skip/not_run。Chisel 缺缓存时可能下载固定 Maven 依赖；这与模型 HTTP 调用不同。首次从Git获取项目后，先按[快速检查](../README.md)恢复锁定的上游源码。

回归覆盖：

- 完整 JSON 快照、路径/include/大小限制、候选宏隔离、禁止参考 RTL 回填。
- 仅候选编译、公开参数/端口、实际层次；参数分支也不能借用 TB 提供设计模块。
- 独立功能判据、错误输出/缺模块/超时拒绝；CPU 软件成功字符串不能替代 AXI 结果检查。
- 两组相同反馈和预算、独立对话、Skill 读取与 HTTP 计数、整项目重构接受/回退。
- 三语言源码评分、真实 UART 缺 FIFO→修复；Chisel 缺模块→修复→重新展开，以及 Scala/RTL 成对回退。
- FMA 独立 oracle/确定性向量再生、计算/互连语义故障、固定归档完整性及导入不覆盖原件。

## 全量参考与候选验证器

仓库不保留运行产物目录和历史报告；`data/` 只保留任务、需求、来源和测试。下面命令按需创建本地 `artifacts/project-rtl/`，其全部内容均被Git忽略。也可通过 `--output` 选择其他输出位置。首次检出后，安装好[所需工具](环境与依赖.md)，可用以下命令生成本地证据（不调用模型）：

```bash
python3 scripts/project_dataset.py --verify-reference --output artifacts/project-rtl/reference
python3 scripts/verify_project_replay.py --negative-controls --compact --output artifacts/project-rtl/candidate/verilog
python3 scripts/verify_project_replay.py --language systemverilog --negative-controls --compact --output artifacts/project-rtl/candidate/systemverilog
python3 scripts/verify_project_replay.py --language chisel --negative-controls --compact --jobs 1 --output artifacts/project-rtl/candidate/chisel
```

每条命令要求其输出目录不存在，不会覆盖旧证据。已有完整证据可直接检查；需要重新生成时先将旧输出目录备份到其他位置。也可用 `--output /tmp/<新目录>` 做独立验收，但下面两项回归检查只读取表中的固定路径。

| 本地证据路径 | 预期正向项目数 | 预期错误输出对照数 |
| --- | ---: | ---: |
| `artifacts/project-rtl/reference/summary.json` | 32 | 32 |
| `artifacts/project-rtl/candidate/verilog/summary.json` | 27 | 27 |
| `artifacts/project-rtl/candidate/systemverilog/summary.json` | 30 | 30 |
| `artifacts/project-rtl/candidate/chisel/summary.json` | 2 | 2 |

证据齐全后，显式启用两项哈希检查：

```bash
RTL_VALIDATE_EVIDENCE=1 PYTHONPATH=src:tests python3 -m unittest -v \
  test_project_dataset.ProjectDatasetTests.test_published_reference_evidence_is_complete_and_unchanged \
  test_project_generation.ProjectGenerationDataTests.test_published_candidate_evidence_matches_current_validator_and_sources
```

也可运行 `RTL_VALIDATE_EVIDENCE=1 python3 -m unittest discover -s tests -v`，在完整回归中一并核对。启用后证据缺失、哈希不匹配或验证结果不合格均报错，不会静默跳过。空日志也属于完整证据的一部分，但无需将其提交到Git。

以 summary/report 和日志为准；summary 锁定清单/验证器哈希，report 锁定源码、日志和故障注入文件。修改验证器后必须重新执行，不能仅回填旧报告哈希。负向对照必须成功编译并产生明确功能失败，单纯超时或缺少成功标记不算证据。

`--compact` 只清理可重建的 vvp/VCD/固件副本和 sbt target 缓存，保留源码、命令、报告及日志。原版兼容性和回放改写详见[数据集说明](../data/project-rtl/README.md)；未放宽候选策略。有限仿真不证明穷尽正确、PPA、IEEE认证或物理CDC签核。
